Introducción a Portal Pilot

Portal Pilot es una plataforma SaaS ERP con inteligencia artificial integrada, diseñada para empresas hondureñas. Incluye facturación electrónica SAR, inventario, contabilidad, nómina y bots RPA automatizados.

Portal Pilot está disponible como aplicación múltiple: Web (navegador), Móvil (iOS/Android), Desktop (Windows/macOS/Linux) y Workspace (gestor de escritorio).

¿Qué incluye?

  • Facturación Electrónica SAR/DEI — Cumplimiento normativo hondureño
  • Inventario Multi-Almacén — Control en tiempo real con stock mínimo
  • Contabilidad — Estados financieros, balances, impuestos
  • Nómina Hondureña — IHSS, RAP, decimoctavo
  • Asistente IA — Groq API (nube)
  • Bots RPA — Automatización de tareas con editor visual
  • Modo Offline — Funciona sin conexión a internet
PRIMEROS PASOS

Instalación de Portal Pilot

Descarga e instala Portal Pilot en tu dispositivo (web, móvil o escritorio). Disponible para Android, iOS, Windows, macOS y Linux.

1

Descarga la app

Ve a portalpilot.hn/download y selecciona tu sistema operativo.

2

Ejecuta el instalador

Windows: haz doble clic en el .exe. macOS: arrastra a Applications. Linux: chmod +x PortalPilot && ./PortalPilot

3

Completa el onboarding

Selecciona el tipo de negocio, cliente y operación. Estas preferencias se guardan localmente y determinan los módulos sugeridos.

4

Crea o usa tu cuenta

Al finalizar, la app te lleva a Acceder. Inicia sesión o abre el registro web para crear la cuenta y completar los datos de tu empresa.

5

Entra al panel

Después de autenticarte, verás los módulos asignados según el área de negocio y los permisos de tu empresa.

El onboarding no crea una cuenta ni inicia sesión por sí solo. La cuenta debe completarse y validarse antes de usar el ERP.

PRIMEROS PASOS

Tu primera factura

Veamos cómo crear tu primera factura electrónica en menos de 2 minutos.

1

Ve a Facturación

En el menú lateral, haz clic en Facturación → Nueva Factura.

2

Selecciona el cliente

Elige un cliente existente o crea uno nuevo con su nombre y RTN. El sistema autocompleta datos si ya está registrado.

3

Agrega productos

Busca productos por nombre o código de barras. La IA sugiere productos frecuentes para ese cliente.

4

Envía al SAR

Haz clic en Enviar. El sistema genera automáticamente la factura electrónica con código QR y la almacena en el SAR.

Tip IA: El asistente detecta si falta información del CAI o rangos por agotarse y te alerta antes de enviar.

WORKSPACE

Facturación Electrónica SAR

Portal Pilot genera facturas electrónicas conformes a la normativa del SAR (Servicio de Administración de Rentas) de Honduras, incluyendo códigos QR, CAI válido y formato DEI.

Configurar CAI

1

Ir a Configuración → Facturación SAR

Selecciona "Configurar CAI" en el menú de empresa.

2

Ingresa tu CAI

Escribe el CAI vigente tal como aparece en tu resolución. El sistema valida el formato automáticamente.

3

Define los rangos autorizados

Establece el rango inicial y final de facturación. El sistema calcula automáticamente cuántas facturas puedes emitir.

El sistema te notificará cuando te queden menos del 10% de facturas disponibles en tu rango actual.

Generar Factura

  • Selecciona o crea un cliente (requiere nombre y RTN)
  • Agrega productos/servicios con cantidades y precios
  • Aplica impuestos (ISV 15% se calcula automáticamente)
  • Haz clic en "Enviar al SAR" — se genera factura electrónica con QR
  • Descarga PDF o comparte enlace directo al cliente
WORKSPACE

Gestión de Inventario

Control total de productos, almacenes y stock en tiempo real con alertas automáticas de stock mínimo.

Crear Producto

  • Nombre: Nombre descriptivo del producto
  • Código SKU: Código único de identificación
  • Precio de compra: Costo de adquisición
  • Precio de venta: Precio al público
  • Stock mínimo: Nivel mínimo de alerta
  • Almacén: Ubicación física del producto

Multi-Almacén

Administra múltiples ubicaciones físicas. Cada almacén tiene stock independiente y se pueden transferir productos entre ellos. Las transferencias quedan registradas en el historial con auditoría completa.

La IA detecta patrones de venta y sugiere reordenar productos antes de quedarse sin stock.

WORKSPACE

Contabilidad

Módulo contable completo con estados financieros, balances y reportes fiscales automáticos.

Funciones Principales

  • Estado de Resultados por período
  • Balance General
  • Libro de Compras y Ventas
  • Reporte de Retenciones
  • Cálculo automático de ISV
  • Conciliación Bancaria

Reportes

Genera reportes en PDF o Excel para declaraciones fiscales. El sistema integra directamente los datos de facturación SAR, eliminando el doble registro.

WORKSPACE

Nómina Hondureña

Cálculo automático de nómina con deducciones de ley hondureñas: IHSS, RAP, decimoctavo, decimocuarto.

Deducciones Automáticas

  • IHSS: Instituto Hondureño de Seguridad Social — 2.5% salario, 1.5% patrono
  • RAP: Retiro Alimentario para Pensionados — 1.5% empleado, 2% patrono
  • Decimoctavo: Bono de 1 mes / 12 × días trabajados
  • Decimocuarto: Bono de 1 mes / 12 × días trabajados
  • ISR: Impuesto Sobre la Renta según tabla vigente

El sistema genera automáticamente los reportes para INSS y RAP listos para presentar al patrono.

WORKSPACE

Asistente de Inteligencia Artificial

Portal Pilot integra IA en la nube potenciada por Groq API para análisis inteligente, automatización de procesos y asistentes virtuales por módulo. Procesamiento rápido y seguro desde la nube.

Modelos Disponibles

ServicioUso PrincipalRequisitos
Groq APIContabilidad, facturación, análisis financiero, chat, reportesConexión a internet

Configurar

Ve a Configuración → IA y selecciona tu proveedor. La IA se activa automáticamente según tu plan.

Groq API es el proveedor recomendado. Ofrece procesamiento rápido y bajo costo para tareas contables hondureñas.

WORKSPACE

Modo Offline

Portal Pilot Workspace funciona completamente sin conexión a internet para operaciones esenciales.

Disponible Offline

  • ✅ Crear y enviar facturas (se sincronizan al reconectar)
  • ✅ Gestionar inventario
  • ✅ Consultas contables
  • ✅ Generar reportes
  • ✅ Usar IA local (Gemma 3N)

Requiere Conexión

  • ❌ Envío de facturas al SAR (se encola y envía al reconectar)
  • ❌ Bots RPA y automatizaciones
  • ❌ Sincronización multi-usuario
  • ❌ Actualizaciones del sistema

Cuando recuperas conexión, todas las operaciones offline se sincronizan automáticamente con el servidor.

ENTERPRISE

Bots RPA Enterprise

Automatiza tareas repetitivas con bots de Robotic Process Automation. Crea agentes que ejecutan flujos de trabajo cuando ocurren eventos (emails, CRON, webhooks, manuales).

Crear tu primer Bot

1

Ir a Enterprise → Bots RPA

Haz clic en "Nuevo Agente" para iniciar la configuración.

2

Selecciona el trigger

Elige cuándo se activa el bot: al recibir un email, en una fecha/hora programada (CRON), al recibir un webhook HTTP, o manualmente.

3

Configura la acción IA

Define qué modelo usar (Gemma 3N recomendado) y el prompt del sistema. Ejemplo: "Extrae el monto del email y genera una factura en el ERP".

4

Conecta pasos en el Flow Editor

Usa el editor visual para encadenar acciones: condición → delay → webhook → acción DB. Arrastra nodos y conéctalos.

5

Activa el bot

Guarda y activa. El bot aparecerá en la grilla de agentes con estado "Activo" y métricas en tiempo real.

Los bots se ejecutan en background. Monitorea su actividad en la consola de logs en tiempo real.

ENTERPRISE

Editor de Flujos (Flow Editor)

Editor visual drag & drop para construir pipelines de automatización con nodos conectados.

Tipos de Nodos

NodoDescripciónEjemplo
TriggerPunto de inicio del flujoEmail recibido, CRON, Webhook
CondiciónEvalúa una expresiónSi monto > 1000 → ruta A
DelayEspera un tiempo determinadoEsperar 5 minutos
WebhookEnvía HTTP requestNotificar a Slack, Telegram
DBOperación en base de datosCrear registro, actualizar stock
IAProcesamiento con modeloClasificar email, extraer datos

Ejemplo: Auto-facturar desde email

Trigger (Email) → IA (Extraer datos) → Condición (¿Cliente existe?) 
  ├─ Sí → DB (Crear factura) → Webhook (Notificar)
  └─ No → DB (Crear cliente) → DB (Crear factura) → Webhook (Notificar)
ENTERPRISE

Configuración de IA en Bots

Cada bot puede usar un modelo de IA diferente. Configura el modelo, temperatura y prompt del sistema.

Opciones de Configuración

  • Modelo: Groq API (nube) — configuración por defecto
  • Temperatura: 0.0 (determinista) a 1.0 (creativo). Para contabilidad usa 0.0-0.2
  • Prompt del sistema: Instrucciones específicas para el bot. Ej: "Eres un asistente contable. Extrae montos y conceptos de emails."
  • Max tokens: Límite de respuesta del modelo (512-2048)

Groq API es el proveedor recomendado para bots. Ofrece procesamiento rápido y bajo costo para tareas de facturación y análisis financiero hondureño.

ENTERPRISE

Triggers y Webhooks

Los triggers determinan cuándo se activa un bot. Webhooks permiten activar bots externamente.

Tipos de Trigger

TriggerDescripciónUso típico
EmailSe activa al recibir un emailAuto-facturar desde solicitudes
CRONEjecuta en horario programadoReportes diarios, recordatorios
WebhookHTTP POST a una URLIntegraciones externas
ManualActivación manual desde UITareas bajo demanda

Endpoint de Webhook

Cada bot genera una URL única tipo:

POST https://api.portalpilot.hn/webhook/bot/{bot_id}

Envía un POST con JSON y el bot procesará los datos según su flujo configurado.

SERVERLESS

Crear Serverless Function

Portal Pilot Serverless permite crear funciones backend personalizadas ejecutadas en la nube.

1

Ir a Serverless → Nueva Function

Selecciona "Crear Function" en el dashboard.

2

Escribe tu código

Usa el editor integrado. Soporta JavaScript/Node.js. Ejemplo: procesar pagos, transformar datos, integraciones API.

3

Configura el endpoint

Define la ruta (ej: /api/mi-funcion), método HTTP y variables de entorno.

SERVERLESS

Desplegar Function

Haz clic en "Deploy" para publicar tu function. Se ejecuta en entorno aislado con escalado automático.

Las functions se despliegan en subdominios únicos tipo: mi-funcion.portalpilot.hn

Monitoreo

  • Logs en tiempo real desde la consola
  • Métricas de invocaciones, latencia y errores
  • Alertas por email si hay fallos
API

Autenticación API

Portal Pilot usa JWT (JSON Web Token) para autenticar peticiones API. El token se obtiene al iniciar sesión y se envía en cada petición.

Headers Requeridos

Authorization: Bearer <tu_token_jwt>
Content-Type: application/json

Login — Obtener Token

POST/api/login
// Request
{
  "email": "usuario@empresa.com",
  "password": "tu_password"
}

// Response 200
{
  "token": "eyJhbGciOiJIUzI1NiIs...",
  "user": {
    "id": "abc123",
    "email": "usuario@empresa.com",
    "nombre": "Juan Pérez",
    "role": "admin"
  }
}

// Response 401
{ "error": "Credenciales inválidas" }

Rate limit: 10 intentos de login cada 15 minutos por IP. Los tokens expiran en 24 horas. Usa POST /api/refresh para renovar.

Refresh Token

POST/api/refresh

Renueva el token JWT antes de que expire. Requiere autenticación.

// Response 200
{ "token": "eyJhbGciOiJIUzI1NiIs...(nuevo)" }

Registro

POST/api/registro
// Request
{
  "email": "nuevo@empresa.com",
  "password": "password123",
  "nombre": "María López",
  "empresa": "Mi Empresa S.A."
}

// Response 201
{ "message": "Cuenta creada. Verifica tu correo.", "userId": "abc123" }

Verificación de Email

POST/api/enviar-codigo-verificacion

Envía un código de verificación al correo registrado.

Recuperación de Contraseña

POST/api/recuperacion

Envía un enlace de recuperación al correo. Rate limit: 3 req / 15 min.

POST/api/recuperacion/verificar

Verifica el código de recuperación y restablece la contraseña.

Verificar Email Existente

GET/api/check-email?email=correo@ejemplo.com
// Response 200
{ "exists": true }

Health Check

GET/api/health

Verifica el estado del servidor. No requiere autenticación.

// Response 200
{ "status": "ok", "uptime": 12345 }
API

Referencia de Endpoints

Todos los endpoints marcados con 🔒 requieren autenticación JWT en el header Authorization.

Tenants (Empresas)

GET/api/tenants 🔒

Lista todas las empresas. Soporta paginación y búsqueda.

// Query params: ?page=1&limit=20&search=nombre
// Response 200
{
  "tenants": [{ "id": "abc123", "nombre": "TechCorp", "plan": "business", ... }],
  "total": 45,
  "page": 1,
  "pages": 3
}
POST/api/tenants 🔒

Crea una nueva empresa.

// Request
{
  "nombre": "Nueva Empresa",
  "rtn": "0801-1234-567890",
  "direccion": "Tegucigalpa",
  "giro": "Comercio",
  "plan": "starter"
}

// Response 201
{ "id": "xyz789", "nombre": "Nueva Empresa", ... }
GET/api/tenant/:id 🔒

Obtiene los detalles de una empresa específica.

PUT/api/tenants/:id 🔒

Actualiza los datos de una empresa. Puede enviar solo los campos a modificar.

// Request (parcial)
{ "plan": "business", "nombre": "TechCorp Actualizado" }
DELETE/api/tenants/:id 🔒

Elimina una empresa y todos sus datos. Operación irreversible.

GET/api/debug/tenants/:id 🔒

Información de debug de una empresa (solo para diagnosticar problemas).

Usuarios

GET/api/users 🔒

Lista todos los usuarios. Soporta paginación y búsqueda por nombre o email.

// Query params: ?page=1&limit=50&search=juan
// Response 200
{
  "users": [{ "id": "u123", "email": "juan@...", "nombre": "Juan", "role": "user", ... }],
  "total": 12,
  "page": 1
}
GET/api/users/:id 🔒

Obtiene los detalles de un usuario específico.

POST/api/users 🔒

Crea un nuevo usuario. Requiere rol admin.

// Request
{
  "email": "nuevo@empresa.com",
  "password": "temporal123",
  "nombre": "Carlos López",
  "role": "user"
}
PUT/api/users/:id 🔒

Actualiza un usuario (nombre, email, rol, avatar, banner). El usuario solo puede actualizar su propio perfil.

// Request
{ "nombre": "Carlos Actualizado", "role": "admin" }
DELETE/api/users/:id 🔒

Elimina un usuario. No se puede eliminar a uno mismo.

Archivos (Upload)

POST/api/upload 🔒

Sube archivos (avatars, banners) a Supabase Storage.

// Request: multipart/form-data
// Campo: file (imagen JPG/PNG, máx 5MB)
// Campo: type (opcional: "avatar" | "banner")

// Response 200
{ "url": "https://storage.supabase.co/..." }

Seguridad

POST/api/alerta-no-autorizado

Reporta un intento de acceso no autorizado. Rate limit: 10 req / 15 min.

// Request
{
  "email": "usuario@empresa.com",
  "ip": "190.100.50.xx",
  "reason": "Contraseña incorrecta"
}

Notificaciones (Bots)

POST/api/notify/onboarding 🔒

Envía notificación de bienvenida al completar onboarding.

POST/api/notify/activation 🔒

Envía notificación de activación de cuenta.

Diagnóstico

GET/api/diagnostico

Estado detallado del sistema: Supabase, NocoDB, email, uptime. No requiere auth.

// Response 200
{
  "supabase": { "connected": true },
  "nocodb": { "configured": true },
  "email": { "configured": true },
  "uptime": 86400
}

Test Email

GET/api/test-email

Envía un correo de prueba para verificar la configuración SMTP.

Configuración Pública

GET/api/config

Información pública del servidor (versión, funcionalidades habilitadas). No requiere auth.

Base URL: Todos los endpoints están bajo https://portal-pilot.vercel.app/api/...
